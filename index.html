      3. [배포] → [새 배포] → 유형: 웹 앱, 실행 사용자 ‘나’, 액세스 권한 ‘모든 사용자’로 배포합니다. 이미 배포했다면 [배포 관리] → 수정 → 새 버전으로 다시 배포합니다.
      4. 발급된 웹 앱 URL(…/exec)을 아래 칸에 저장합니다. 제출은 [성찰기록]·[상담신청]·[역량진단] 탭에, 교사 데이터는 [교사관리] 탭에 쌓이고, 관제실의 [시트와 동기화]로 되가져옵니다.
      5. 예전 6열 형식의 [성찰기록] 탭이 있다면 탭 이름을 바꿔 보관하세요. 새 13열 탭이 자동으로 만들어집니다.
      🛠️ 연동이 안 될 때 — 자주 생기는 오류와 해결법
      ① 웹 앱 URL 형식이 맞는지
      주소는 https://script.google.com/macros/s/로 시작하고 /exec로 끝나야 합니다. 스프레드시트 주소(docs.google.com/spreadsheets/…)나 /dev로 끝나는 테스트 주소는 동작하지 않습니다.
      ② 학생 제출이 시트에 쌓이지 않을 때 (액세스 권한 누락)
      Apps Script 편집기 [배포] → [배포 관리] → 연필(수정) → 액세스 권한을 ‘모든 사용자’로, 실행 계정을 ‘나’로 바꾸고 버전을 ‘새 버전’으로 선택해 [배포]합니다.
      ③ ‘모든 사용자’ 항목이 보이지 않을 때
      학교(기관) 구글 계정은 외부 공개가 막혀 있을 수 있습니다. 개인 구글 계정으로 스프레드시트와 스크립트를 새로 만들어 배포하세요.
      ④ 스크립트를 고쳤는데 그대로일 때
      코드를 저장만 해서는 반영되지 않습니다. [배포 관리] → 연필(수정) → 버전 ‘새 버전’ → [배포]를 해야 하며, 이렇게 하면 URL은 바뀌지 않습니다. [새 배포]를 누르면 URL이 바뀌므로 이 칸에 새 주소를 다시 넣어야 합니다.
      ⑤ “동기화 키가 배포된 스크립트와 다릅니다”가 나올 때
      스크립트 맨 위 SYNC_KEY 값과 이 창의 동기화 키가 글자 하나까지 같은지 확인하고, 고쳤다면 ④처럼 새 버전으로 배포합니다.
      ⑥ 처음 배포할 때 “확인되지 않은 앱” 경고가 나올 때
      본인이 만든 스크립트이므로 [고급] → [(프로젝트 이름)(으)로 이동] → [허용] 순서로 승인합니다.
      ⑦-2 제출 코드·이름 확인·확인 번호가 동작하지 않을 때
      스크립트가 옛 버전입니다. 관제실이 만든 최신 스크립트 코드로 교체하고(동기화 키는 기존 키를 그대로 넣기) [배포 관리] → 새 버전으로 배포하세요.
      ⑦ 확인 방법
      학생용 주소(?student)에서 성찰 1건을 제출한 뒤 스프레드시트 [성찰기록] 탭에 행이 생겼는지 보고, 관제실 [시트와 동기화]를 눌러 불러와지는지 확인합니다.

      🪙 YEEP 모의펀딩 팀별 집계

      학생 한 명당 마지막 제출만 집계합니다. 창을 열어 두면 15초마다 새로 고칩니다.

      학생 개별 성장 카드

      이름 없이 ‘배운 점’만 무작위 순서로 보여 줍니다. 학급을 고르면 그 학급 성찰만 표시됩니다.

        👥 C레벨 팀 편성표

        1-10차시에 팀을 만들고 CEO(이끔이)·CPO(기록이)·CTO(상상이)·CMO(칭찬이)를 배정합니다. 2-02차시에는 [역할 한 칸씩 교대]로 새 역할에 도전하게 합니다. 이 표는 교사 기기(동기화 시 [교사관리] 시트)에만 저장되고 학생 화면·배포 파일에는 들어가지 않습니다. 칠판 모드에서는 팀 활동 차시에 이 편성표가 함께 보입니다.

        인원별 운영 — 4명: 1인 1역할 · 5명: CTO 또는 CMO를 2명이 공동으로 · 3명: CEO가 CPO 겸임 · 6명: CTO·CMO 각 2명
